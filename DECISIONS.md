# Decisions

Defaults picked during the build when the brief left room.

## Architecture
- **Single repo, single process.** Vite + React + TypeScript client, Fastify server in `server/` serving `dist/` and `/api/*` on `process.env.PORT` (default 3000). The server runs TypeScript directly with `tsx`, so `npm start` needs only Node.
- **Contracts first.** `src/contracts/` holds every shared shape: data schemas (`types.ts`), HTTP API and typed client (`api.ts`), world layout and anchors (`scene.ts`), event bus (`events.ts`), colliders (`colliders.ts`), interactables (`interaction.ts`), material ids (`materials.ts`), style tokens (`style.ts`), assets (`assets.ts`), per-frame runtime state (`runtime.ts`).
- **Each workstream exports fixed component names** from its folder's `index.tsx`. `src/world/World.tsx` and `src/App.tsx` already import them, so workstreams never edit shared files.
- **State:** one Zustand store (`src/state/store.ts`) for reactive state, the event bus for one-shot signals, and `src/state/bridge.ts` to map UI events to overlay changes. Per-frame data (player pose, pin positions, fps, joystick) lives in the non-reactive `runtime` object.
- **Collision uses simple AABB colliders** (`colliders.ts`) instead of Rapier. The room is a box full of box-shaped furniture. Circle-vs-AABB in 2D is cheap, deterministic and testable, and it avoids a roughly 2 MB WASM physics engine.
- **Room size is 20 m x 16 m x 4 m.** From the centre that is 12.9 steps (0.75 m each) east/west and 10.2 steps north/south, after subtracting the player radius.
- **Layout:** the bulletin board is on the north wall (you face it at spawn), the wish-list chalkboard is on the east wall, the desk terminal is on the west wall, the gate door is on the south wall (behind spawn), the living area is centre-east, and the trophy shelf/calendar is on the west wall.
- **Geometry and textures are procedural** (low-poly primitives and canvas textures) to keep the initial load small and licences clean. Any CC0 file used is listed in CREDITS.md.
- **Wishlist `done` flag** added beyond the brief so items can be marked done.
- **API shape:** `GET /api/data` returns the whole dataset (rooms, reviews, wishlist, crew), `POST /api/entries` saves a room and its review together, and `PUT /api/wishlist` replaces the list. The data is small, so simple semantics win.
- **Test hooks:** `window.__ESCAPE__` exposes the store, the bus and a teleport helper for Playwright QA.
- **Versions:** React 19.2, R3F 9, drei 10, three 0.186, Vite 8, Tailwind 4, Zod 4, TypeScript 5.9 (typescript-eslint does not support TS 7 yet), ESLint 9, Vitest 5, and Playwright 1.63.0, pinned to match the preinstalled Chromium.

## Integration
- **Spawn moved from z=5.5 to z=3.5** (still facing north, gate door behind you) so the bulletin board, the hero of the room, reads bigger on arrival. The living-area path tests still pass.
- **Room textures tile at real-world scale.** The room shell uses world-planar UVs (0.5 UV units per metre), while the shared materials' default repeats assume 0..1 UVs, which made the floor look like a noisy carpet. The room now uses `getTiledMaterial` clones sized per surface (floor tile 2.5 m x 1.25 m = honey planks ~0.31 m wide). The plank texture draws the seams, so the separate groove mesh was dropped.
- **Lighter, warmer ceiling.** `LIGHT.hemiGround` is now `#b07a5e` (warm bounce off the floor) and the lighting rig reads it from the style contract. Beams use honey `woodLight` instead of `woodDark`. The board spot and the north LED spill were toned down so the top of the board isn't blown out.
- **Stacking order:** touch controls z 5 < reticle z 20 < HUD z 30 < overlays z 40-50 < toast z 60 < loading screen z 80. The HUD and the touch controls hide while an overlay is open.
- **One toast system:** the confirm screen's "Pinned to the board!" goes through the shell toast slot.
- **Draft-level flags are notes, not fields:** `extraction.fallback` shows as an info note at the top of the confirm screen; only `room.*` / `review.*` flags become "Check this" chips.
- **Audio waits for a real user activation** (`navigator.userActivation.hasBeenActive`). The automation autostart of the loading screen is not treated as a gesture, so headless runs don't log AudioContext warnings.
- **e2e isolation:** `playwright.config.ts` gives every run a fresh temp `DATA_DIR` and blanks the API/Sheet keys, so tests always run in mock + seed mode and never touch `.data/`. It does not reuse an already running server unless `E2E_REUSE_SERVER` is set.
- **Walkable from the exact centre (QA #4).** From (0, 0) you can walk at least 10 steps (7.5 m) north, south, east and west, and along the diagonals. The floor lamp moved off the z = 0 line to just behind the couch's north arm (`LAMPS.floorLamp` = [6.75, 1.75, 0.7]; the light follows because lighting reads `LAMPS`). The gate door now opens a right angle so the leaf stands against its hinge side, its doorway collider hugs the wall (0.12 m deep instead of 1 m), and a narrow `gate:door-leaf` box covers the open leaf off the centre line. Board, chalkboard, wrap-shelf and gate colliders moved into small pure `colliders.ts` files, so `src/player/reach.test.ts` registers every real collider and walks from the centre. North and south reach is 7.51 m (board and doorway slabs are 0.12 m deep), east/west 9.65 m.
- **Precompressed static assets (QA #3).** No compression dependency: `server/precompress.ts` (node:zlib) writes `.br` and `.gz` siblings after `vite build` and at server startup when missing or stale, and `@fastify/static` `preCompressed` serves them by `Accept-Encoding` with `Vary: accept-encoding`. Precompressing at build time lets brotli run at quality 11 once instead of on every request.

## Deploy fixes
- **Node floor is 20.19+ / 22.12+**, matching Vite 8's `engines`. `package.json` engines and the `npm start` preflight both enforce it, so an older Node fails with a clear message instead of a confusing build error.
- **Railway build command is just `npm run build`.** Railpack already runs `npm ci` in its install step, and running `npm ci` again in the build step can fail with `EBUSY` on the builder's `node_modules/.cache` mount.

## Phase 2
- **Foundation (contracts v2, schema, wiring).** Phase 2 contracts live in `src/contracts/models.ts`, `routes.ts` (every route with its auth level, owning workstream and schemas) and `errors.ts`; the Phase 1 files stay for the 3D room. Server route modules are listed once in `server/routes/registry.ts`, and client pages once in `src/router.tsx`, so workstreams only edit their own files.
- **Driver: node-postgres + Drizzle, PGlite without `DATABASE_URL`.** Local runs, Vitest and Playwright use PGlite (in-process WebAssembly Postgres with `pg_trgm`), so no external Postgres is needed anywhere but Railway. Vitest builds one migrated PGlite template per run to keep each test file's database start under a second.
- **Better Auth tables are plural** (`users`, `sessions`, `accounts`, `verifications`; adapter `usePlural: true`), with our extra user columns `handle` (unique, case-insensitive), `display_name`, `is_admin`, `onboarded_at`.
- **Text ids everywhere**, prefixed (`vis_`, `rev_`, `ven_`...), because Better Auth uses text ids and prefixes make logs readable.
- **Migrations run twice on deploy, safely:** Railway's `preDeployCommand` (`npm run db:migrate`) and again at server start, both under a Postgres advisory lock. Start-up waits at most `MIGRATION_TIMEOUT_MS` (30 s); if the database is down the server still listens, `/health` stays `{ ok: true }`, database routes answer 503 `db_unavailable`, and it retries every 30 s. The Railway health-check timeout went from 60 s to 120 s.
- **Google Sheets storage removed.** Signed-in users' data is Postgres. The read-only seed demo (`seed/reviews.json` + local overlay) is kept only for signed-out visitors of the Phase 1 routes (`/api/data`, `/api/entries`, `/api/wishlist`), so the 3D room and the e2e suite keep working until workstream 20 moves the room to the Phase 2 API. Phase 1 entries saved by a signed-in user map to venue/game/visit/review rows (`server/db/dataset.ts`); venues created that way have country `ZZ` (unknown) until corrected.
- **Every route goes through `defineRoute`,** which enforces the auth level, validates input with the contract and parses output with it. Output parsing strips unlisted fields, a second guard against leaking emails.
- **Transcripts are author-only** (`ReviewV2.transcript` is null for anyone else) and **the friends leaderboard has no streaks**, because `/privacy` says voice notes, transcripts and streaks are visible only to their owner.
- **Spending caps are counted per UTC day** in `usage_counters` (per user and a `__global__` row), reserved atomically before a provider call and released if it fails. Defaults: 20 min transcription and 30 extractions per user, 6 h and 1000 globally, overridable by `CAP_*` env vars.
- **Escape of the Day numbering** starts at #1 on 2026-10-26 (`DAILY_EPOCH`).
- **Extra dependencies installed up front** for the bundles: `drizzle-orm`, `drizzle-kit`, `pg`, `@electric-sql/pglite`, `better-auth`, `@fastify/cookie`, `@fastify/multipart` (25 MB, one file per request), `@fastify/rate-limit` (opt-in per route), `openai`, `hyparquet` + `hyparquet-compressors` (Foursquare Parquet), `idb-keyval`, `qrcode`, and for tests `fake-indexeddb` and `@testing-library/user-event`. No image-rendering package: Open Graph images use the static brand images. `google-auth-library` was removed with the Sheet adapter.
- **Client routing:** a ~100-line router (`src/router.tsx`) instead of a library. The 3D room is lazy-loaded too (`src/desktop.tsx`), so `/m` and the public pages never download three.js. `/welcome` holds the landing page until sign-in decides what `/` shows.
- **Auth (3): Better Auth with Google only, no telemetry, no stored Google tokens.** Scopes are exactly `openid email profile` (`disableDefaultScope`). Account-create/update hooks null the access, refresh and ID tokens because we never call Google APIs. Email/password, update-user, account linking, token and account-listing endpoints are disabled. Cookies are prefixed `myescapes.`, http-only, `SameSite=Lax`, and `Secure` in production or behind an https URL. Sessions last 30 days, refreshed daily. Better Auth's origin/callbackURL checks stay on in tests too.
- **Auth base URL:** `PUBLIC_URL`, else `BETTER_AUTH_URL`, else `https://$RAILWAY_PUBLIC_DOMAIN` (Railway injects it), else inferred from the request (local runs). No new Railway variable is needed.
- **Auth needs `BETTER_AUTH_SECRET`.** Without it (and outside NODE_ENV=test) sign-in is off: `/api/auth/*` answers 404 and everyone is signed out. Tests use a fixed test-only secret.
- **Test login:** `POST /api/test/login` exists only when NODE_ENV=test. It mints a real Better Auth session through a server-only endpoint that is installed only in tests and never routed over HTTP. Tests prove both are 404 under production, development and unset NODE_ENV.
- **A request without a session cookie never touches the database** for auth, so public pages keep working while Postgres starts.
- **Onboarding = display name + @handle.** `onboardedAt` is stamped the first time both are set. Handles are stored lowercase and unique case-insensitively, the contract's reserved list is never available, and a signed-in user's own handle counts as available to them. The client prefills the handle from the Google name (else the email's local part) and the display name from Google.
- **"Before any review can be public":** public queries must AND `authorIsPublic()` (server/auth/users.ts), so reviews by users without a public name stay off public pages and out of averages. Routes that set visibility can call `assertCanPublish` (403 `onboarding_required`).
- **Account deletion:** visits with nobody else holding an account (owner or accepted) are deleted with their guests, puzzles, photos and pending tags. On the other visits the person's row becomes the plain guest name (their display name) with status `accepted`, and `created_by` is cleared. Reports about their reviews and photos are deleted, reports they sent are kept without a reporter, and reviews copied from theirs lose the link. Directory contributions stay without pointing at them. Usage counters are removed. Everything else (reviews, photos, friendships, invites, notifications, wish list, daily results, sessions, Google links) goes by cascade. Requires `{ "confirm": "DELETE" }` and clears the session cookies.
- **Export** includes every visit I own, accepted, was tagged on or reviewed (others' reviews only as their visibility allows, never their transcripts or emails), all my reviews with transcripts, wish list, friends, invites I made, Escape of the Day results, notifications and reports I sent. It is sent with `Content-Disposition: attachment`.
- **`GET /api/logs?with=&without=`** matches a crew member by user id, @handle or guest name (case-insensitive). Pending users count as crew. Rows are newest first.
- **Integration (b01-auth):** the desktop room (`src/desktop.tsx`) is wrapped in `<OnboardingGate>`, so a signed-in user without a display name and @handle sees onboarding first; signed-out visitors see the room unchanged. The mobile shell and landing page mount the gate and the sign-in button in their own workstreams (13, 19).
- **Directory source host (bundle 5/6/8).** The official `foursquare/fsq-os-places` dataset on Hugging Face is gated (401 without an accepted-terms token) and its files redirect to HF CDN hosts this build container can't reach, so the importer reads the same Apache-2.0 release (2025-02-06) from the Fused mirror on Source Cooperative's public S3 bucket. `--base hf` with `HF_TOKEN` reads the official copy instead.
- **Directory seed is committed, loaded on deploy.** The importer writes `seed/directory/<region>.json.gz` + `manifest.json` (about 0.5 MB for 42 regions, ~3,350 venues); the server loads it in the background once the database is ready when no imported venue exists or the manifest version changed. Upserts on `fsq_id`, a lease row in `directory_seed_state` (created by the loader, not a Drizzle migration) keeps one loader at a time, and `/health` never waits for it. `DIRECTORY_SEED=off` disables it; it is off by default under `NODE_ENV=test`.
- **What counts as an escape room:** Foursquare's "Escape Room" category, or an escape-room name ("Escape Room", "Escape Game", "Escapology", "방탈출", "脱出ゲーム", "密室逃脱"...) unless every category says bar/shop/hotel/etc. Closed places are dropped. Name matches added ~25% more US venues (2,206 raw records vs 1,705).
- **De-duplication:** same venue when names are similar (trigram Dice >= 0.5 on the distinctive part of the name, e.g. "Fayetteville" in "Escape Room Fayetteville") and under 75 m apart, or under 300 m with a shared phone or website host and a related name. The record with the most complete fields (and an escape-room-looking name) wins; the others fill gaps and stay in `sources`.
- **City regions group under the city:** venues in the London, Tokyo, ... boxes get city "London" etc. and an empty region (city slug `london-gb`); the Foursquare locality moves into the address. Country regions (US, CA) keep the Foursquare locality and state.
- **Chains (`brand`)** are inferred from a website host shared by venues in 3+ cities (e.g. Escapology, Breakout Games).
- **Imported venues keep their slug and id across re-imports;** a seed slug already used by another venue gets the last 6 characters of the Foursquare id appended. A user's applied correction to an imported venue (a `user` row with `applied` fields in `sources`) is not overwritten by later imports.
- **Contributions:** any signed-in user can add a venue or game; an exact or near duplicate (same name in the city, or similar name under 75 m; same name at the venue for games) returns the existing one. The creator and admins edit freely; anyone else can only fill empty fields, and their other changes are stored in `sources` as suggestions. Slugs never change on edit, so links keep working. Only http(s) websites are stored.
- **Game page reviews** (until 33 supplies them): public, non-hidden reviews by onboarded authors, plus friends-only reviews when the viewer is the author or an accepted friend; private reviews never. Aggregates count public, non-copied reviews; visit facts (escape rate, time) count each visit once. The review cursor is opaque base64url (`{"o": offset}`), 20 per page.
- **Directory search** uses pg_trgm (`similarity`/`word_similarity` over the GIN trigram indexes) when the extension exists and falls back to ILIKE otherwise. Matcher scores: venue = weighted mean of name 0.65, city 0.2, distance 0.15 (of the hints given); game = 0.65 name + 0.35 venue.
- **Integration (b02-directory):** directory review queries require both @handle and display name (same rule as `authorIsPublic()`), so the Google profile name never shows publicly. `buildTestApp` sets `DIRECTORY_SEED=off` by default so tests that set `NODE_ENV=production` don't start the background seed load; e2e keeps the seed load on (real directory data).
- **Transcription (10):** `POST /api/transcribe` reads the upload into memory only, sends it to OpenAI (`gpt-4o-transcribe`, override `OPENAI_TRANSCRIBE_MODEL`, with an escape-room vocabulary prompt), then zero-fills the buffer before answering; audio never touches disk or the database. Without `OPENAI_API_KEY` it returns the sample voice note (mock). Seconds counted = the larger of the recorder's `durationSeconds` and a file-size floor (40 kB/s compressed, 192 kB/s wav/flac), trimmed to the provider-measured duration when it reports one; mock mode counts too so the meter and the 429 typing fallback can be tested without a key. A retried `clientId` returns the same transcript from a 15-minute in-memory cache, without a second provider call or charge. Provider failures are 502 `upstream` with `fallback: 'typing'`. Burst limit 30/min per IP.
- **Extraction v2 (11):** caps count Claude calls only (mock is free and is the over-cap fallback anyway). Signed-out callers (Phase 1 3D room) share one `__anonymous__` bucket with the per-user limit, so no IPs are stored. Over a cap, or when the counter can't be written, extraction fails closed to the mock extractor with a `notice`; a Claude failure that falls back to mock gives its unit back. Hints are snapped to nearby directory names (50 km, trigram similarity >= 0.55) when the phone sends a location. Burst limit 20/min per IP.
- **Photos (24).** Stored in Postgres, at most 1 MB each (the browser aims for 1600 px and 400 KB, JPEG), at most 4096 px on the long side, 30 per visit, captions up to 280 characters. The server decides the type from the file's magic bytes (JPEG, PNG or WebP only; SVG and everything else get 415) and reads width and height from the image header. Owners and accepted participants add photos; owners, accepted and pending participants can view them (pending people need to see the visit to answer "that was me"). Anyone else sees a photo only when the visit has a public, non-hidden review on a non-hidden game, and the photo isn't hidden. Only the uploader removes a photo, not even the visit owner or an admin (admins hide instead). Photos are served with `Cache-Control: private, max-age=300` and `nosniff`. Strangers get 404, never 403, so they can't tell a visit exists.
- **Moderation (25).** Admins are users with `is_admin` or an email listed in `ADMIN_EMAILS` (comma separated, case-insensitive; applied in `server/context.ts`). You can only report what you can see; a repeat report of the same thing while it's open returns the first one. Resolving with "hide" hides the target and closes every open report on it; "dismiss" closes just that report. Hiding sets `hidden_at` on reviews and photos and `status = 'hidden'` on games and venues; unhiding a game or venue sets it back to `active` only if it was hidden (a closed venue stays closed). The queue defaults to open reports, newest first, 200 at most. No admin screen tonight (cut-order item); the API is complete.
- **Permission suite (38).** `server/authz.test.ts` tests only routes that exist, with no pending `todo`s. Rules for routes still being built (visits, reviews, friends, tagging, leave, delete, account deletion) are added by those bundles or the integrator.
- **Integration (b05-photos):** a photo is public only through a public, non-hidden review whose author has a public name (`authorIsPublic`), on a game and venue that are not hidden, matching the directory's public-review rule. `ADMIN_EMAILS` is mapped only in `server/context.ts` (the auth bundle does not map admins by email).
